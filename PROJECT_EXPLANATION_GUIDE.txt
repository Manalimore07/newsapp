१. प्रोजेक्टचे उद्दिष्ट (PROJECT OVERVIEW)
================================================================================
हा एक आधुनिक न्यूज ॲप्लिकेशन (News App) आहे.
या ॲपमध्ये वापरकर्त्याला ताज्या बातम्यांची यादी दिसते, बातमीवर क्लिक केल्यावर
तिचे सविस्तर वाचन करता येते, मूळ बातमीच्या वेबसाईटवर ब्राउझरमध्ये जाता येते,
बातम्या सर्च करता येतात, आणि इंटरनेट बंद असले (Offline Mode) तरीही पूर्वी वाचलेल्या
बातम्या आपोआप दिसतात. तसेच ॲपमध्ये Dark Mode आणि Light Mode ची सुविधा आहे.

हा प्रोजेक्ट 'Clean Architecture' आणि 'BLoC (Cubit)' पॅटर्ननुसार बनवला आहे,
जो मोठ्या IT कंपन्यांमध्ये आणि प्रॉडक्शन ॲप्समध्ये वापरला जातो.

================================================================================
२. कोणती लायब्ररी का वापरली? (TECHNOLOGIES & WHY WE USED THEM)
================================================================================

१) flutter_bloc (Cubit):
   - काय आहे: State Management लायब्ररी.
   - का वापरली: ॲपमध्ये डेटा लोड होताना Spinner दाखवणे (Loading State), डेटा आल्यावर
     बातम्या दाखवणे (Loaded State), किंवा एरर आल्यावर मेसेज दाखवणे (Error State)
     हे काम BLoC/Cubit मुळे अत्यंत सोपे आणि सुरक्षित होते.

२) hive & hive_flutter:
   - काय आहे: अतिशय वेगवान, लाईटवेट NoSQL लोकल डेटाबेस.
   - का वापरली: युझरने एकदा बातम्या लोड केल्या की त्या फोनच्या लोकल मेमरीमध्ये सेव्ह
     होतात. त्यामुळे युझर ऑफलाइन (विना इंटरनेट) असतानाही ॲप क्रॅश न होता बातम्या दाखवते.
     SQLite पेक्षा Hive खूप वेगवान आणि सेटअप करायला सोपा आहे.

३) get_it:
   - काय आहे: Service Locator (Dependency Injection) टूल.
   - का वापरली: आपल्या वेगवेगळ्या क्लासेसना (उदा. Cubit, Repository, UseCase)
     एकमेकांशी जोडण्यासाठी. यामुळे कोडमध्ये कुठेही 'new' कीवर्डने क्लास बनवावा
     लागत नाही, कोड सुटसुटीत आणि टेस्ट करायला सोपा राहतो.

४) equatable:
   - काय आहे: दोन Dart Objects ची तुलना करणारी लायब्ररी.
   - का वापरली: जेव्हा State बदलते, तेव्हाच स्क्रीन पुन्हा री-बिल्ड (re-render) व्हावी,
     नको असताना स्क्रीन सतत रिफ्रेश होऊ नये म्हणून हे वापरले जाते.

५) url_launcher:
   - काय आहे: मोबाईलच्या डिफॉल्ट ब्राउझरमध्ये लिंक उघडणारे पॅकेज.
   - का वापरली: बातमीच्या मूळ प्रकाशकाची (Publisher) खरी वेबसाईट Chrome किंवा
     Safari मध्ये उघडण्यासाठी हे वापरले आहे.

६) intl:
   - काय आहे: Date आणि Number formatting लायब्ररी.
   - का वापरली: सर्व्हरकडून आलेली तारीख (उदा. 2026-10-23T08:30:00Z) युझरला समजेल
     अशा सुंदर फॉरमॅटमध्ये (उदा. Oct 23, 2026 • 8:30 AM) दाखवण्यासाठी.

३. CLEAN ARCHITECTURE म्हणजे काय? (WHAT IS CLEAN ARCHITECTURE?)
================================================================================
Clean Architecture चे सर्वात महत्त्वाचे तत्त्व:
"UI, बिझनेस लॉजिक आणि डेटाबेस यांना एकमेकांपासून वेगळे ठेवणे."

आपण कोड ३ मुख्य लेयर्समध्ये विभागला आहे:

+-------------------------------------------------------+
| 1. PRESENTATION LAYER (UI + State Management)         |
|    - Screens, Widgets, NewsCubit, ThemeCubit          |
+---------------------------+---------------------------+
                            | (कॉल करते)
                            v
+-------------------------------------------------------+
| 2. DOMAIN LAYER (Core Business Logic)                 |
|    - Entities, UseCases, Abstract Repository Contract |
+---------------------------+---------------------------+
                            ^ (डेटा पुरवतो)
                            |
+-------------------------------------------------------+
| 3. DATA LAYER (Data Sources & Models)                 |
|    - ArticleModel, MockDataSource, HiveLocalSource    |
+-------------------------------------------------------+

फायदा:
जर उद्या आपल्याला Mock डेटा काढून थेट Live API जोडायची असेल, तर फक्त Data Layer मध्ये
बदल करावा लागतो. Domain Layer आणि UI ला हातही लावावा लागत नाही!

   - ॲपमध्ये येणारे एरर्स (ServerFailure, CacheFailure, NetworkFailure) हँडल

3. core/theme/app_theme.dart:

7. domain/usecases/search_articles_usecase.dart:
   - सर्च क्वेरीनुसार बातम्या शोधण्याची स्वतंत्र ॲक्शन.

[C] DATA LAYER (lib/features/news/data/) - डेटा आणणे आणि साठवणे
--------------------------------------------------------------------------------
8. data/models/article_model.dart:
   - ArticleEntity चा विस्तार (extends).
   - fromJson(): सर्व्हरच्या JSON मॅपचे Dart ऑब्जेक्टमध्ये रूपांतर करतो.
   - toJson(): Dart ऑब्जेक्टचे पुन्हा JSON मॅपमध्ये रूपांतर करतो (Hive मध्ये साठवण्यासाठी).
   - यात Null Safety ची विशेष काळजी घेतली आहे, जेणेकरून एखादी व्हॅल्यू null
     असेल तरी ॲप क्रॅश होत नाही.

9. data/datasources/news_mock_data_source.dart:
   - 'assets/data/news_mock.json' फाईलमधून ८ रिअल बातम्या लोड करतो.
   - यात मुद्दाम ६५०ms चा delay ठेवला आहे जेणेकरून खऱ्या API सारखा लोडिंग अनुभव येतो.

10. data/datasources/news_local_data_source.dart:
    - Hive डेटाबेस वापरून बातम्या फोनच्या मेमरीमध्ये सेव्ह करतो आणि ऑफलाइन असताना
      तिथून वाचून परत देतो.

11. data/repositories/news_repository_impl.dart:
    - NewsRepository चे खरे इम्प्लिमेंटेशन.
    - हे प्रथम Remote/Mock वरून ताज्या बातम्या आणते आणि Hive मध्ये सेव्ह करते.
    - जर काही अडचण आली किंवा इंटरनेट नसेल, तर लगेच Hive मधून डेटा काढून देते.

५. ॲपमधील मुख्य फीचर्स कसे काम करतात? (FEATURE WORKFLOW)
================================================================================

१) डेटा कसा येतो आणि दिसतो? (Data Flow):
   main.dart -> NewsCubit.fetchNews() -> GetArticlesUseCase -> NewsRepositoryImpl
   -> NewsMockDataSource (JSON वाचतो) -> Hive मध्ये सेव्ह करतो -> NewsLoaded State
   -> HomeScreen वर ArticleCard ची यादी दिसते.

२) ऑफलाइन मोड कसा चालतो? (Offline Workflow):
   युझरने इंटरनेट बंद केले तरी NewsRepositoryImpl आधीच्या फेचमधील सेव्ह केलेल्या
   बातम्या Hive मधून शोधून आणते. त्यामुळे युझरला कधीही रिकामी स्क्रीन दिसत नाही.

३) सर्च कसा चालतो? (Search Workflow):
   सर्च बारमध्ये काहीही टाईप केले की NewsCubit.searchNews(query) कॉल होतो.
   हे टायटल, डिस्क्रिप्शन आणि मजकुरामध्ये तो शब्द शोधून फक्त जुळणाऱ्या बातम्या दाखवते.

४) मूळ बातमी उघडणे (Browser Link):
   'Read Full Original Story' वर क्लिक केल्यावर `url_launcher` पॅकेजच्या मदतीने
   `launchUrl(Uri.parse(url))` एक्झिक्युट होते आणि फोनच्या ब्राऊझरमध्ये लिंक उघडते.

७. मुलाखतीसाठी महत्त्वाचे प्रश्न आणि उत्तरे (TOP INTERVIEW Q&A)
================================================================================

प्रश्न १: तुम्ही कोणता स्टेट मॅनेजमेंट पॅटर्न वापरला आणि का?
उत्तर: "मी BLoC मधील Cubit वापरले आहे. मोठ्या ॲप्लिकेशन्समध्ये BLoC हे इंडस्ट्री
स्टँडर्ड मानले जाते. या प्रोजेक्टमध्ये Events चे अतिरिक्त क्लासेस न लिहिता कोड
स्वच्छ आणि समजायला सोपा राहावा म्हणून मी Cubit निवडले."

प्रश्न २: Clean Architecture चे मुख्य ३ लेयर्स कोणते आणि त्यांचा फायदा काय?
उत्तर: "Presentation, Domain, आणि Data हे ३ लेयर्स आहेत. याचा मुख्य फायदा म्हणजे
UI, बिझनेस लॉजिक आणि डेटाबेस एकमेकांपासून वेगळे राहतात. यामुळे टेस्टिंग सोपे होते
आणि भविष्यात डेटा सोर्स बदलणे (उदा. Mock वरून Live API वर जाणे) अत्यंत सोपे होते."

प्रश्न ३: तुम्ही खरी NewsAPI का नाही वापरली?
उत्तर: "NewsAPI च्या फ्री प्लॅनवर दिवसाला फक्त १०० रिक्वेस्ट्सची मर्यादा असते आणि
मोबाईल आयपीवर अनेकदा CORS किंवा 426 एरर येतो. कोड रिव्ह्यू करताना कोणत्याही एररशिवाय
परीक्षकाला ॲप सुरळीत तपासता यावे म्हणून मी NewsAPI च्या हुबेहूब स्कीमाचा Mock JSON
डेटा वापरला आहे. आणि Clean Architecture मुळे फक्त १ लाईन बदलून कधीही खरी API जोडता येते."

प्रश्न ४: Offline Caching साठी Hive का निवडले?
उत्तर: "Hive हा Pure Dart NoSQL डेटाबेस आहे. तो SQLite पेक्षा अत्यंत वेगवान आहे,
त्याला कोणत्याही नेटिव्ह बायनरीची गरज नसते आणि की-व्हॅल्यू स्वरूपात डेटा काही
मिलीसेकंदांत वाचता व लिहिता येतो."
